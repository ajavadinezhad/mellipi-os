# Mellipi 0.1.9 — everyday essentials and recovery

This release adds the essentials needed to administer, back up and recover a minimal Linux + Mellipi installation. It keeps controls on demand and does not add a desktop backup daemon or update poller.

## Added

- **Standalone Users & passwords and Date & time settings.** AccountsService and timedated perform privileged changes through normal graphical authorization. Account removal preserves the user's files and refuses the signed-in account, active sessions and removal of the last unlocked administrator. Changing your own password uses the normal PAM `passwd` flow. Date/time supports installed time zones, automatic time and explicitly entered UTC time.
- **Backups & recovery in Settings.** Back up desktop settings and explicitly chosen personal files/folders. Verify SHA256 records before restoring. Restore personal files into a new folder, preserving empty folders, modification times and safe owner-executable permissions. Schedule desktop settings for the next login with pre-restore copies and protection for edits made after scheduling. Browse uses its own ordinary desktop window; Cancel does not affect other apps.
- **A working-version recovery path.** Save exact installed desktop package versions, including compatibility packages. `mellipi-recover` shows a recovery command and restores only known exact-version desktop packages through normal signed APT sources, with confirmation. The complete desktop profile adds **Mellipi Recovery** at sign-in: a password-authenticated repair terminal that skips the compositor, startup apps and user shell startup scripts. It keeps a TTY fallback available.
- **An on-screen keyboard inside the secure locker.** Mouse and touch input can enter printable ASCII using Shift, Symbols, Back, Space and Unlock. The locker retains upstream PAM/authentication code; it does not grant another application permission to inject lock input. Native touch streams are cancelled at lock/output/device/VT boundaries.
- **Resume recovery hooks and diagnostics.** The native compositor and event-driven idle helper can reset KMS, retire stale page-flip queues and re-arm input without intentionally changing lock ownership or application processes. The after-resume listener remains available when idle timers are disabled; automatic locks receive the actual theme/settings file. Bounded recovery handles inactive-seat and transient connection errors, and native logs are drained promptly. These changes are not a visual S3 acceptance claim; see the reproduced virtual-graphics limitation below.
- **Update-repository maintenance.** A weekly GitHub health check verifies both current and compatibility endpoints, warns before metadata/key expiry, and maintains one actionable repository issue on failure. Private-key signing stays on the maintainer's machine. A reviewed renewal helper authenticates the existing archive and renews signed metadata without replacing package/source bytes. Renewal and deployment remain manual maintainer operations; the workflow is an alert, not automatic signing. GitHub may disable scheduled workflows after prolonged inactivity, so monthly maintainer review remains necessary.
- **A signed Ubuntu EFI build chain.** The image builder can assemble Ubuntu-signed shim, GRUB and kernel, and the installer preserves that chain on the target. No private firmware key, MOK enrollment or validation bypass is embedded. See the final exact-image acceptance below; structural signatures alone do not establish Secure Boot support.
- **Read-only hardware reporting and complete regression sources.** Diagnostics distinguish detected devices/capabilities from tested physical workflows. The corresponding source offer includes the new tests and recovery/administration/boot/update tools.

## Upgrading

Existing settings and compatibility identifiers are preserved. Package installation does not log you out or restart the compositor. Save work and perform one ordinary logout/login to activate native compositor/session-level changes. Full-profile installations gain the sign-in Recovery option; core-only installations keep their distribution's existing recovery sessions and the TTY helper.

## Remaining limits

The lock password field is still a Cairo control and **does not expose an AT-SPI password object**. Full secure-field screen-reader access is not implemented. The on-screen layout is **fixed US printable ASCII**; physical keyboards retain their configured XKB layout and Unicode input. Native touch currently follows the first mapped output; per-device calibration/output assignment and physical touchscreen acceptance remain separate work.

The QEMU/virtio-vga S3 visual-resume test above is a known failed workflow, including on the independent Xorg baseline. Physical suspend/lid-close, mixed-scale multi-monitor hotplug, additional GPU/driver families, real headset recording and physical DDC brightness changes are not certified by a VM or read-only capability report. Secure Boot depends on the machine's firmware trust/DBX/SBAT policy; unsigned third-party kernel modules and other firmware policies need separate acceptance. This is not a verified root filesystem or TPM attestation feature.

Backups are **not encrypted**, do not preserve ownership/ACLs/xattrs or symlinks, and are not system images or live database snapshots. They are bounded to 50,000 file/folder entries and 32 GiB per backup. Exact-version APT recovery needs retained versions in a reachable trusted repository; it is not an offline rescue partition, kernel rollback or boot-time filesystem snapshot. The Recovery terminal requires the distribution's working Xorg/LightDM and normal login authentication, and has no session lock: exit it before leaving the machine.

A minor known issue: Files can initially show the runtime working directory; Home in its sidebar navigates normally.
