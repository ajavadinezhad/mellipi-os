# Release notes template

Use **Mellipi VERSION** for every GitHub release title. For prereleases, use GitHub’s pre-release flag and say **Preview** in the first paragraph. Tag names keep the leading `v`.

Open with a short paragraph on what this release is for and who can use it.

### New features
- Name each new capability and explain what it lets people do.

### Improvements
- Explain how an existing workflow changed.

### Bug fixes
- Describe the symptom and what now works. Use fixes confirmed by the release history.

### What we tested
- Say which image or package was tested and which workflows passed.

### Known limits
- State any limits that affect installation or everyday use.

### Downloads
- Link the ISO, checksums, packages, and verification evidence as applicable.

Give each change its own bullet. Add a sentence when it helps a reader understand the impact. Omit empty categories, and link technical notes for test logs and detailed compatibility information. Keep the published body in `docs/release-notes/vVERSION.md`.
